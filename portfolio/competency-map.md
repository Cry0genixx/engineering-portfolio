# Engineering Competency map

**Version:** 0.1\
**Status:** Draft\
**Last updated:** 2026-09-04

## Purpose

This document maps current engineering competence, existing evidence and areas where stronger portfolio evidence should be developed.

The competenct map is intended to:

* identify existing strengths,
* identify weakly documented competence,
* reveal important capability gaps,
* guide project selection,
* prevent unnecessary duplication of already well-established skills,
* and track techincal development over time.

The ratings in this document are deliberately conservative and should be revised when stronger evidence become available.

---

## Rating system

### Competence level

| Level | Description |
|---|---|
| 1 - Awareness | Basic theoretical familiarity. Requires guidance for practical application. |
| 2 - Developing | Can perform basic tasks and understand common consepts, but experience is limited. |
| 3 - Independent | Can perform typical work independently and troubleshoot common problems. |
| 4 - Advanced | Strong practical competence, good judgement and ability to solve complex problems. |
| 5 - Expert / Core Strength | Extensive practical experience and deep competence developed over many years. |

### Evidence Level

| Level | Description |
|---|---|
| 0 - None | No meaningful evidence currently available. | 
| 1 - Claimed / Educational | CV entry, course, certificate or educational exposure. | 
| 2 - Practical Evidence | Concrete work experience or project experience can be described. | 
| 3 - Strong evidence | Substansial experience, certification or detailed project evidence exists. | 
| 4 - Portfolio Verified | Strong, reviewable and well-documented evidence available through the portfolio. | 

### Portfolio priority

* **P0 - Critical:** Strong portfolio evidence should be developed.
* **P1 - High:** Important differentiator or supporting competence.
* **P2 - Medium:** Useful but not currently critical.
* **P3 - Low:** Existing background already provides sufficient evidence or the skill has limited relevance to the target profile.

## 1. Manufacturing & CNC

| Competency | Competence | Evidence | Gap | Priority | 
|---|---:|---:|---|---|
| CNC machining | 5/5 | 3/4 | Publicly reviewable engineering case. | P3 | 
| G-code / NC programming | 5/5 | 3/4 | Structured example demonstrating advanced application. | P3 | 
| 3-axis machining | 5/5 | 3/4 | Limited need for further evidence. | P3 | 
| 5-axis machining | 4-5/5 | 3/4 | Publicly documentable case. | P3 | 
| CAM programming | 4/5 | 2-3/4 | Portfolio example linking design to machining. | P2 | 
| Toolpath strategy | 4-5/5 | 2-3/4 | Explicit decision documentation. | P2 | 
| Cutting tools and machining parameters | 4-5/5 | 2-3/4 | Formalized technical case. | P2 | 
| Workholding / fixturing | 4/5 | 2/4 | Designed and documented fixture project. | P1 | 
| Tolerances and dimensional control | 4/5 | 2-3/4 | Traceable design-to-inspection example. | P1 | 
| Metrology / inspection | 4/5 | 2-3/4 | Formalized insptection strategy. | P1 | 
| Production troubleshooting | 4-5/5 | 2-3/4 | Sanitized root-cause case studies. | P1 | 
| Production optimization | 4/5 | 2-3/4 | Quantified improvement case. | P1 |
| Manufacturability / DFM | 4-5/5 | 2/4 | Explicit DFM analysis. | P1 |

### Domain Assessment

Manufacturing and CNC represent one of the strongest existing competency areas.

Portfolio work should therefore focus on converting existing practical knowledge into engineering evidence rather than creating basic CNC exercises.

Particular emphasis should be placed on DFM, fixturing, tolerance strategy and integration of machining knowledge into automated systems.
